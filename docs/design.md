# A2A Review Studio 설계안

상태: 사용자 검토용 제안. 아직 구현하거나 GitHub 저장소를 생성하지 않았다.

## 목적

자기소개서와 면접에서 설명할 수 있는 대표 A2A 웹앱을 제작하고 사용자의 GitHub에 등록한다. H-Chat, 사내 API, 회사 교안 원본 없이 독립 실행되어야 한다. Orchestrator의 업무 분배, 전문 에이전트 간 피드백, 최종 결과 종합을 화면과 통신 기록으로 확인할 수 있어야 한다.

## 제안 주제와 대안

추천: 업무 개선 제안서 검토 앱. 사용자가 업무 문제와 개선안을 입력하면 기술·비용·사용자 관점의 전문가가 검토하고 상호 피드백 후 실행안을 제시한다. 여러 지원 직무에 설명하기 쉽고 가상 업무 데이터만으로 재현할 수 있다.

대안 1: 교안과 유사한 보험 심사 예제. 전문 Agent의 역할이 분명하지만 보험 약관과 법적 근거를 별도로 관리해야 한다.

대안 2: 문장 작성·피드백 앱. 구현과 설명이 쉽지만 업무 활용 범위를 보여주기에는 작다.

## 사용자 흐름

1. 샘플 업무 개선안 선택 또는 직접 입력.
2. 검토 시작 후 Orchestrator가 세 전문가에게 초기 검토를 요청.
3. 기술·비용·사용자 전문가가 근거, 우려 사항, 보완 조건을 반환.
4. 각 전문가가 다른 전문가에게 A2A로 한 차례 피드백 요청 후 자신의 검토안을 수정.
5. Orchestrator가 합의점, 남은 이견, 실행 단계, 검증 지표를 종합.
6. 사용자가 전문가별 초안·수정안과 A2A 통신 기록을 확인하고 결과를 Markdown으로 다운로드.

LLM의 숨겨진 사고 과정은 표시하지 않는다. 실제 송수신 메시지, 진행 상태, 명시적으로 생성한 판단 근거만 표시한다.

## 에이전트 역할

- Orchestrator: 업무 분배, 진행 상태 관리, 결과 종합.
- Technical Agent: 구현 가능성, 데이터와 시스템 연동, 기술적 제약 검토.
- Business Agent: 비용, 예상 효익, 측정 가능한 성과 지표 검토. 미제공 수치는 가정으로 표시.
- User Agent: 사용자 흐름, 도입 부담, 현업 활용성과 피드백 검토.

## 구조와 통신

Python FastAPI 백엔드와 브라우저 프런트엔드를 사용한다. 전문가들은 독립 A2A 엔드포인트와 Agent Card를 제공한다. 초기에는 하나의 로컬 서버 아래 경로별로 배치하되 에이전트 호출은 실제 HTTP A2A 통신으로 수행한다. 외부 URL을 사용자가 임의로 지정하는 기능은 넣지 않는다.

공식 A2A Python SDK를 우선 검토해 호환되는 버전을 고정한다. 공식 SDK를 사용하는 목적은 Agent Card와 메시지·작업 처리의 프로토콜 동작을 검증하기 위해서다. 교안의 FastA2A 라이브러리를 그대로 재현하는 것이 필수 조건은 아니다. 설치 가능 버전과 지원 메서드는 구현 계획 단계에서 확정한다.

서버 내부 Python 함수 호출만으로 업무를 위임하는 것을 A2A라고 표시하지 않는다. README에 지원하는 프로토콜 버전·전송 방식·메서드와 미지원 범위를 명시한다.

## 실행 모드

- 데모 모드: API 키 없이 실행. 고정된 예제와 규칙 기반 응답을 사용하며 화면에 ‘LLM 미사용 데모’ 표시. A2A HTTP 통신과 실행 상태 처리는 실제로 수행.
- Claude 모드: 서버 환경변수로 설정한 Anthropic API 키와 모델을 사용해 실제 입력을 분석. 키는 브라우저·로그·Git에 포함하지 않는다.

데모 검증과 실제 모델 검증 결과를 구분한다. 사용 가능한 키가 없으면 Claude 모드는 실제 호출 검증 전 상태임을 명시하고 데모를 AI 분석 완료로 표현하지 않는다.

## 화면

한국어 UI. 입력 영역, 에이전트 관계도와 실행 상태, 전문가별 검토 결과, 최종 실행안, 접을 수 있는 통신 기록으로 구성한다. 모바일에서도 입력과 결과를 읽을 수 있게 배치한다. 요청 진행·완료·부분 실패·전체 실패·빈 결과를 구분해 표시한다.

## 오류와 실행 한도

입력 길이, 실행 시간, 출력 토큰과 피드백 횟수에 상한을 둔다. 피드백은 전문가별 한 차례로 제한해 순환 호출을 막는다. Agent가 실패하면 해당 실패를 표시하며 성공한 결과만으로 만든 종합 결과는 ‘일부 검토 누락’으로 구분한다. 전부 실패하면 성공 결과를 만들지 않는다. 진행 중 중복 제출은 막는다.

## 검증 기준

- API 키 없는 환경에서 샘플 입력부터 결과 다운로드까지 실행된다.
- A2A Agent Card를 조회하고 SDK 클라이언트로 메시지를 전송하는 통합 테스트가 통과한다.
- 전문가 간 피드백 전후 결과와 송수신 기록이 확인된다.
- 동시 실행 시 사건별 데이터가 섞이지 않는다.
- 시간 초과, Agent 실패, 잘못된 입력을 테스트한다.
- 사용자 입력과 모델 출력을 HTML로 직접 삽입하지 않는다.
- 실제 브라우저로 대표 화면과 실행 흐름을 확인한다.
