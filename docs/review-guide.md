# 직접 검토할 부분

## 먼저 화면에서 확인하기

1. README대로 실행하고 `http://127.0.0.1:8765` 접속.
2. **고객 문의 자동 분류** 예제를 선택하고 데모 모드로 검토 시작.
3. 완료 후 **전문가 간 A2A 피드백 6 / 6**, **12 MESSAGES** 확인.
4. **기술 → 피드백 이전 초안 비교하기 → 다른 전문가에게 받은 피드백**을 열어 초안·피드백·수정안 비교.
5. **최종 실행안**에서 실행 단계와 검증 지표 확인.
6. **A2A 통신 기록**을 열어 source, target, phase, message_id, 요청·응답 내용 확인.
7. **결과 내려받기**로 Markdown 파일 저장.
8. 다른 예제로 다시 실행하거나 검토 도중 새로고침해 진행 상태 복구 확인.

데모 답변은 고정된 예시다. 문구 자체의 맞춤 분석 품질을 평가하는 대신 실제 메시지 교환, 상태, 비교·내보내기 기능을 확인한다.

## Claude 키 설정 후 확인할 부분

이 항목은 제작 과정에서 실제 호출로 검증하지 못했다. 서버의 `.env`에 키와 계정에서 지원하는 모델 ID를 넣고 재시작한다. 키를 GitHub나 채팅에 붙여 넣지 않는다.

- Claude 모드가 선택 가능한가?
- 서로 다른 제안을 넣었을 때 각 제안에 맞는 검토가 나오는가?
- 각 전문가는 자신의 관점을 유지하며, 다른 전문가의 피드백을 구체적으로 반영하는가?
- 근거가 부족한 비용·절감 시간·효과를 사실처럼 만들어내지 않는가?
- 최종 결과가 이견과 누락을 숨기지 않는가?
- API 사용량과 검토 시간이 본인이 허용할 범위인가?
- 오류가 생겼을 때 Claude 결과인 것처럼 데모 응답을 보여주지 않는가?

정상 실행은 모델 생성 최대 13회다. API 요금과 품질은 모델과 입력 길이에 따라 달라진다.

## 면접 전에 설명할 수 있어야 할 내용

- Orchestrator의 업무 위임과 A2A 프로토콜 통신은 어떻게 다른가?
- 한 서버인데도 실제 A2A HTTP 통신이라고 설명할 수 있는 근거는 무엇인가?
- `protocol.py`의 SDK 클라이언트와 AgentExecutor는 각각 무엇을 하는가?
- 왜 피드백은 6건이고 전체 A2A 요청은 12건인가?
- 단일 함수 호출로 바꿨을 때 잃는 경계와, HTTP로 구현했을 때 드는 비용은 무엇인가?
- 일부 에이전트가 실패하면 어떤 결과를 남기고 사용자에게 어떻게 알리는가?
- 데모 검증과 실제 LLM 분석 검증은 무엇이 다른가?
- 이 구현에 FastA2A·Deep Agents·MCP가 실제로 포함되는가? (포함되지 않는다.)
